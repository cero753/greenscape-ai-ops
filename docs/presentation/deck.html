The AI core

The model gets a narrow job

What Claude is allowed to do

Read messy site-walk notes → map scope onto the company's real 63-item Phoenix pricing catalog → emit line items with quantities, a confidence score, and an explicit assumption per line. That's retrieval + mapping.

What Claude is not allowed to do

Invent prices. Invent catalog codes. Return prose. Decide anything reaches a client. Judgment stays with Marcus — he stops being the pricing typist, he stays the pricing authority.

That framing is the whole design: the model drafts, the human ships.

"What happens when the model returns garbage?"

Seven layers, all demoable

1 Catalog-constrained pricing

Off-catalog items come back at $0 and flagged for manual pricing — never guessed.

2 Structured output

zod-validated via messages.parse(). The model cannot return prose. One retry, then clean failure.

3 Server-side re-validation

Unknown codes zeroed; prices outside the catalog's min/max band flagged. The model's numbers are never trusted blind.

4 Garbage-input refusal

Nonsense notes produce needs_clarification — a checklist of what to go ask — not a fabricated quote.

5 HITL enforced twice

UI blocks Approve & Send while flagged; the API independently rejects it. Belt and suspenders.

6 Public page isolation

Unguessable UUID token, client-safe fields only — no AI metadata, internal notes, or costs.

7 Async generation

A 30–50s LLM call can't live in a synchronous serverless function — the platform kills it mid-generation. Found this in live testing. Generation runs as a Netlify background function: 202 instantly, UI polls, failures log a generation_failed event instead of vanishing.

Architecture judgment

Where I used an agent — and where I refused to

Workflow · money moves

Proposal generation and reactivation drafting are code-owned control flow. The model does exactly one constrained step; my code decides what happens before and after, validates the output, and gates the send behind a human. Predictable, auditable, cheap.

Agent · open-ended reads

"Ask your pipeline" is a real tool-use loop: Claude gets four read-only DB tools and picks which to call, up to 6 turns, before answering. Same endpoint backs a Slack /ask slash command.

The line: let the model own control flow only where the blast radius is zero. Every Q&A tool is a SELECT. Nothing it can do writes, sends, or spends.
